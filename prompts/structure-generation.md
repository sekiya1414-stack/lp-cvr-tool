# 構造生成プロンプト設計(叩き台)

フェーズ2でAnthropic APIを使い、「どのセクションを・どの順番で・どの訴求軸で
配置するか」というLPの構造自体をLLMで生成する際のプロンプト設計の叩き台。
コピー(文言)そのものの生成は [`copy-generation.md`](copy-generation.md) が担当し、
このファイルは「セクション構成・レイアウト方針」の生成を担当する。

## 前提: デフォルトのCRO仮説

コピー生成と同様、以下は**実データが蓄積されるまでの初期仮説**であり、
A/Bテスト結果が業種別に溜まり次第、実データに基づく知見で上書きしていく。

1. ファーストビューに社会的証明(利用者数、導入企業ロゴなど)を配置すると
   信頼性が向上する
   → デフォルトの構造は `hero → social-proof → pricing → cta` の順とし、
     social-proofをheroの直後(=ファーストビュー〜次画面)に配置する。
2. 長いLPの場合、最初の1画面での離脱率が高いため、価値提案は最上部で
   明確にする
   → hero単体で価値提案が完結する構造を必須とし、価値提案の理解に
     複数セクションのスクロールを要する構成にしない。
3. フォームの入力項目は少ないほどCVRが高い傾向がある
   → cta(最終行動喚起)セクションのフォーム構造は、デフォルトで
     入力項目1〜2個(メールアドレス中心)を基本形とする。
4. 訴求軸(価格・権威・感情など)によって刺さるターゲット層が異なるため、
   最初から複数パターンを試す前提で設計する
   → 1商材につき最低3訴求軸(価格・権威・感情)の構造バリアントを
     並行生成することをデフォルトとする。訴求軸によって、同じ
     `templates/` パーツでも「どのセクションを厚くするか」の比重を変える
     (例: 価格訴求ならpricingセクションを拡張、権威訴求ならsocial-proofを拡張)。

## 入力(想定パラメータ)

- `product_name`: 商材名
- `available_sections`: 利用可能な `templates/` 配下のパーツ一覧
  (`hero` / `cta` / `social-proof` / `pricing` など)
- `appeal_axis`: 訴求軸
- `past_winning_patterns`: (フェーズ3以降)過去の勝ちパターンDBから得られる
  類似業種・訴求軸での高CVR構成データ

## 生成対象(出力)

1. セクションの並び順(配列)
2. 各セクションの比重・強調ポイント(例: 「pricingセクションは3プランではなく
   1プランに絞り、価格の安さを大きく見せる」)
3. 使用する `templates/` パーツ名のマッピング

## プロンプトテンプレート例(叩き台)

```
あなたはCRO(コンバージョン率最適化)に精通したLP構造設計者です。
以下の商材・訴求軸・利用可能パーツに基づき、LPのセクション構成を設計してください。

商材名: {{product_name}}
訴求軸: {{appeal_axis}}
利用可能なセクションパーツ: {{available_sections}}
過去の勝ちパターン(あれば): {{past_winning_patterns}}

# 出力ルール
- ファーストビュー(1〜2セクション目まで)で価値提案が伝わる構成にする
- 訴求軸に応じて、関連の深いセクションの比重を上げる
- 出力は「セクション順」「各セクションの強調ポイント」のJSON形式で返す
```

## 出力フォーマット(想定)

```json
{
  "sections": ["hero", "social-proof", "pricing", "cta"],
  "emphasis": {
    "pricing": "3プラン中、真ん中のプランを最も強調する"
  }
}
```

## フェーズ3との接続(参考)

フェーズ3で勝ちパターンDBが蓄積された後は、`past_winning_patterns` に
「業種 × 訴求軸 × 構成 × 実測CVR」のデータを渡し、初期仮説(上記1〜4)よりも
実データを優先して構造を決定するようプロンプトを更新する想定。

# フェーズ2: 画像生成機能の設計メモ(未実装)

このファイルはフェーズ2で実装予定の「LPヒーロー画像自動生成機能」の設計方針
メモです。**現時点(フェーズ1)ではコードの実装は行いません。** 将来この機能に
着手する際の参照用として残しています。

## 実装予定の機能概要

- `api/generate-image.ts` を新規作成し、商材・ターゲット・訴求軸に応じた
  ヒーロー画像を Stability AI(または DALL-E)API経由で生成できるようにする
  - 入力: 商材名、ターゲットペルソナ、訴求軸(価格 / 権威 / 感情)
  - 出力: 生成された画像ファイル(またはURL)
- 生成した画像は Supabase Storage に保存し、LPの variant ごとに紐付ける
  - 例: `project-a` の `variant-1` に対して1〜数枚の画像を関連付け
- 独自性を高めたい場合、将来的には LoRA による軽量ファインチューニングも検討する
  (自社商材・業種特化のスタイル学習)

## 現時点(フェーズ1〜フェーズ2着手前)の画像運用方針

- LPに必要な画像は Canva を使って手動 / 半自動で作成・差し替える運用とする
- `lp/project-a/variant-1〜3` 内の画像は、一旦プレースホルダー画像
  (`placeholder.jpg` や Unsplash画像のURL参照)を使っておき、Canvaで作成した
  画像に後から差し替えられるようにファイル構成を残しておく
  - 実際、現在の `templates/hero/sample.html` の `{{HERO_IMAGE_SRC}}` は
    Unsplash画像のURLを直接参照する形にしてあり、差し替え時は
    このプレースホルダー値(または `scripts/build.js` 内のvariant設定にある
    `HERO_IMAGE_SRC`)を、Canvaでエクスポートした画像パスに変更するだけで良い

## フェーズ2着手時の検討事項(メモ)

- Stability AI / DALL-E のどちらを使うかは、画質・料金・商用利用条件を
  比較して決定する
- Supabase Storageのバケット設計(project × variant単位でパスを切るか等)
- 生成画像のライセンス・商用利用可否の確認(特にLoRA学習用データの権利関係)
- 画像生成のコストが嵩む場合、キャッシュ・再利用の仕組み(同じ訴求軸なら
  近い画像を使い回す等)を検討する
